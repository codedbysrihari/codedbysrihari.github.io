A Quantum Second Opinion

A paper-stage concept for an uncertainty-gated hybrid classifier. A classical model handles an input first, then routes uncertain cases to a small quantum model. The experiment would test whether that second opinion earns its computational cost.

Research question

When should a classical model ask a quantum model for a second opinion?

Why explore this

My interests in quantum computing and machine learning meet in a practical systems question. A hybrid pipeline could make the decision to call a quantum model observable and measurable. This concept would study where those calls go, which errors change, and what each call costs. Quantum benchmarking and calibration research inform the comparison design. An eventual interface would let visitors inspect an input, its routing decision, and both model predictions.

Working hypothesis

An uncertainty gate may concentrate a limited second-stage budget on difficult inputs. Whether a quantum model helps on those inputs is an open experimental question. The study would compare it with a classical second opinion and random routing under the same evaluation rules.

Experiment design

  1. Generate moons and concentric-circle classification tasks with five fixed dataset seeds. Use 2,400 examples per task and seed, split into 1,200 training, 400 validation, 400 calibration, and 400 final-test examples. Record generator settings and hashes. Create an additional, separately reported input-noise shift set.
  2. Train a logistic-regression first stage and use predictive entropy as its uncertainty score. Fit preprocessing on training data. Select regularization on validation data, fit temperature scaling on calibration data, and freeze the first stage before routing evaluation.
  3. Train a two-qubit variational classifier and a small multilayer perceptron on the same complete training partition. Specify angle encoding, one or two circuit layers, and a fixed readout. Cap tuning at twelve trials per second-stage family per task and dataset seed. Refit each selected configuration with three initialization seeds.
  4. Choose entropy thresholds on the calibration partition targeting 5%, 10%, 25%, and 50% second-stage calls. A routed example receives the second-stage prediction. Freeze thresholds before testing and report the actual call fraction, which can change on unseen or shifted inputs.
  5. Compare the first stage alone, quantum and MLP second opinions under the identical gate, each second stage applied to every input, and random-routing controls. Match realized call counts for the random controls. Keep the same first-stage predictions and test examples for paired comparisons. Repeat random routing with twenty fixed masks per dataset seed and budget, share masks between second-stage models, and average these controls within each dataset seed.
  6. Start with exact simulator expectations. Freeze the quantum models and repeat evaluation with 128 and 1,024 measurement shots. Use several independent shot seeds to distinguish sampling variation from training variation. Retain predictions and routing records for a later interactive walkthrough.

Evaluation plan

  • Report balanced accuracy, macro F1, and paired changes against the first stage alone. Show routed-subset accuracy and the counts of first-stage errors corrected or newly introduced by each second stage.
  • Plot predictive quality against the observed second-stage call fraction. Compare quantum and MLP routing at each target budget and show the random-routing references.
  • Record total inference time, first-stage overhead, circuit executions, measurement shots, and tuning time on the same documented host. Report simulator timings as simulator measurements.
  • Keep task, dataset seed, model initialization, and shot seed in the experiment records. Show every dataset-seed result, average initialization repeats within each dataset seed, and report paired uncertainty intervals with dataset seeds as the independent units.
  • Repeat the frozen gate on the input-noise shift set. Track changes in call rate and accepted first-stage errors. Analyze cases where uncertainty routing spends its budget without improving the final prediction.

Limits and risks

  • Two small synthetic task families provide a controlled first experiment. Generalization to real applications would require additional datasets and stronger first-stage models.
  • The proposed quantum model runs on a classical simulator. Hardware benefit and computational advantage would require dedicated hardware experiments and a separate resource analysis.
  • A confidence gate can miss confidently wrong predictions. The study must retain all first-stage errors in its report, including cases that never receive a second opinion.
  • A routed subgroup can be small at the lowest call fraction. Counts and uncertainty intervals would accompany every subgroup comparison, and five dataset seeds give limited precision.

Implementation plan

  1. Write the routing contract, data split manifest, model definitions, and frozen evaluation protocol.
  2. Implement the first stage, MLP comparison, and random-routing control before adding the quantum stage.
  3. Run the paired comparison, measurement-shot checks, and input-noise stress test.
  4. Publish the experiment record and build a viewer of individual routing decisions.

Planned outputs

  • A reproducible hybrid-classification harness with auditable routing decisions.
  • A research report covering predictive quality, query budgets, cost, and failure cases.
  • A planned interactive viewer connecting each second-opinion call to its input and outcome.
