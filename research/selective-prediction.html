Reliable machine learning

The Confidence Gap

A proposed study of travel intent models that can defer uncertain requests. The experiment would measure whether calibration and confidence thresholds reduce accepted errors when wording, destinations, and request styles change beyond the training distribution.

Research question

When should a travel assistant ask a question before making a prediction?

Why explore this

A traveller can express the same intent in many ways. A model may classify familiar requests well while becoming overconfident on unfamiliar wording. This proposal connects my travel-product experience with a concrete reliability question. Published work on calibration, selective classification, and dataset shift motivates an experiment that measures both the predictions a system accepts and the requests it defers.

Working hypothesis

A confidence threshold selected on held-out calibration data may reduce errors among accepted predictions. The study would test whether that benefit persists under controlled language shifts and how much request coverage is sacrificed.

Experiment design

  1. Create an explicitly authored benchmark of approximately 900 single-intent travel requests across transport, accommodation, and activity categories. Document label rules, ambiguous cases, and authorship. Build a separate challenge set with unfamiliar phrasing, locations, and out-of-scope requests.
  2. Group paraphrases by their originating intent scenario before splitting data into training, model-selection, calibration, and final-test partitions. Fit text preprocessing on training data. Reserve the final test and challenge labels for the final evaluation.
  3. Compare a TF-IDF logistic-regression baseline with a small neural classifier using the same training examples. Limit model-selection trials in advance and record model size, training time, random seeds, and preprocessing settings.
  4. Compare always-predict behavior, an uncalibrated confidence threshold, and temperature-scaled confidence with a threshold. Choose thresholds on calibration data to target 60%, 80%, and 95% coverage, then freeze them before testing.
  5. Evaluate ordinary requests and each shift type separately. A small React demonstrator would show the predicted intent, confidence, and a clarification prompt whenever the policy defers. Each example would be linked to the benchmark record that produced it.

Evaluation plan

  • Report risk–coverage curves, where risk is the error rate among accepted requests and coverage is the fraction accepted. Include the always-predict point and a random-deferral reference.
  • Report macro F1 across all in-scope requests, Brier score, and reliability diagrams before and after calibration. Record expected calibration error with the binning rule stated.
  • Measure the fraction of out-of-scope requests incorrectly accepted and the fraction of valid requests deferred. Compare these by shift type and intent class.
  • Repeat model training across five seeds and retain per-example predictions. Show uncertainty intervals and paired method differences. Treat each scenario group as the resampling unit when bootstrapping related paraphrases.

Limits and risks

  • An authored benchmark has limited linguistic and behavioural diversity. Any conclusion would apply first to this benchmark, with evaluation on consented real requests as a later extension.
  • Calibration quality on familiar data can change under distribution shift. The study would report empirical behaviour for each tested shift and document cases where confidence fails.
  • Single-intent classification captures one component of a travel assistant. Recommendation quality and the usefulness of clarification questions would require separate evaluations.

Implementation plan

  1. Specify the label guide, scenario groups, and locked evaluation protocol.
  2. Implement baselines and validate the split and preprocessing pipeline.
  3. Run the frozen comparison and assemble failure-case analyses.
  4. Publish a reproducible report and a demonstrator using recorded benchmark outputs.

Planned outputs

  • A versioned benchmark specification and reproducible experiment configuration.
  • A report covering risk, coverage, calibration, and documented failure cases.
  • A React walkthrough that makes the defer-or-predict decision visible.
